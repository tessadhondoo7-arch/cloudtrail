# CloudTrail Threat Detection & MITRE ATT&CK Mapper

A local-only, defensive Python tool that analyses AWS CloudTrail JSON log files,
detects suspicious activity with explainable rules, maps findings to MITRE ATT&CK
techniques, and measures detection quality against labeled ground truth.

> **Status:** Milestone 4: first detection rule (`iam_policy_modification`). More rules to come.

## Goals

- Load AWS CloudTrail JSON files
- Validate and normalize events
- Detect suspicious patterns using explainable rules
- Map supported findings to verified MITRE ATT&CK techniques
- Evaluate detections against labeled ground truth (precision, recall, F1, confusion matrix)
- Provide a CLI and, later, a Streamlit dashboard

## Safety principles

- **Local only:** no AWS account or credentials required; works on log files on disk.
- **Defensive only:** detection and analysis, no offensive tooling.
- **No secrets in the repo:** use synthetic data; real logs and credentials are git-ignored.

## Usage: load and validate CloudTrail files

```powershell
python -m cloudtrail_mapper data/synthetic
python -m cloudtrail_mapper data/synthetic/valid_basic.json --show 10
```

The loader accepts files (`.json`, `.json.gz`) and directories. It never crashes on
bad input; instead it reports:

- **errors**: a file or record was skipped (invalid JSON, missing `Records`,
  missing `eventTime`/`eventName`/`eventSource`, unparseable time, non-object record)
- **warnings**: a record was kept but looks odd (empty file, missing `eventID`,
  unusual region or source IP, duplicate `eventID`)

Normalization: times → UTC, `eventSource` and region lowercased, IPs canonicalized,
AWS-service callers flagged, best identity name extracted from `userIdentity`.

## Pipeline modules

| Module | Responsibility |
|---|---|
| `schemas.py` | Data shapes: `NormalizedEvent`, `ValidationIssue`, `LoadResult` |
| `loader.py` | Read files safely and run the full pipeline (`load_events`) |
| `normalize.py` | Validate records, normalize fields, remove duplicate `eventID`s |

Sample files in `data/synthetic/` are entirely synthetic: placeholder account IDs
(`111122223333`) and documentation-only IP ranges (RFC 5737 / RFC 3849).

## Synthetic scenarios and ground truth

`data/synthetic/scenarios/` holds 10 labeled scenario files (benign baseline,
suspicious activity, hard negatives, and edge cases). `data/labels/ground_truth.csv`
labels every record. See [docs/synthetic_dataset.md](docs/synthetic_dataset.md) for
the scenarios, the label format, and how precision/recall/F1 will be scored.

```powershell
python -m cloudtrail_mapper data/synthetic/scenarios --show 0
```

The dataset is generated by `scripts/generate_synthetic_dataset.py`.

## Detection rules

Run all implemented rules and print findings with their evidence:

```powershell
python -m cloudtrail_mapper data/synthetic/scenarios --show 0 --detect
```

| Rule ID | Description |
|---|---|
| `iam_policy_modification` | successful IAM policy, trust, boundary or group-membership changes ([docs](docs/rules/iam_policy_modification.md)) |

A finding means the activity deserves review; it is never treated as proof of
malicious intent. MITRE ATT&CK mappings are intentionally empty until verified.
